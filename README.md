# Shop App

Каталог товаров с локальными фильтрами по категории и цене, страницей товара с рейтингом, корзиной и оформлением заказа. Данные загружаются из [Fake Store API](https://fakestoreapi.com).

Flutter **3.47.9**, Dart **3.13.7**.

## Стек и архитектура

- **BLoC/Cubit** — состояния экранов. Общий Bloc корзины последовательно обрабатывает изменения количества и сохранение.
- **Dio + Retrofit** — общий HTTP-клиент, типизированные DTO и единая обработка ошибок. **connectivity_plus** сообщает о смене подключения; доступность API проверяется запросом.
- **shared_preferences** — для небольшого каталога и корзины достаточно JSON-снимков. Изменения корзины публикуются после успешного сохранения.
- **auto_route** — типизированные маршруты и вкладки с сохранением состояния.
- **theme_tailor** — генерация служебного кода `ThemeExtension` для общей темы приложения.

Код разделён по фичам в `lib/features`: `presentation`, `data`, `domain`. Общие API и DTO — в `lib/api`, инфраструктура — в `lib/core`, тема и компоненты — в `lib/foundation` и `lib/ui_kit`. Локализация общая для проекта.

## Запуск

**FVM (Flutter Version Management)** управляет версиями Flutter для разных проектов. Здесь версия SDK закреплена в [.fvmrc](.fvmrc): **3.47.9**. Это помогает всем участникам использовать одинаковую версию Flutter и входящего в него Dart.

Установите FVM по [официальной инструкции](https://fvm.app/documentation/getting-started/installation). Затем выполните из корня проекта:

```sh
fvm install
fvm use 3.47.9
fvm flutter pub get
fvm flutter run
```

`fvm install` скачивает SDK из `.fvmrc`, а `fvm use` подключает его к проекту и создаёт ссылку `.fvm/flutter_sdk`. Команды `fvm flutter …` и `fvm dart …` используют выбранный SDK.

Для запуска из IDE укажите путь к Flutter SDK: `<путь к проекту>/.fvm/flutter_sdk`. [Справочник команд FVM](https://fvm.app/documentation/guides/basic-commands).

Без FVM можно использовать Flutter 3.47.9, убрав префикс `fvm` у команд Flutter.

## Офлайн-режим

После успешной загрузки каталог сохраняется локально. Без сети показываются сохранённые товары и индикатор «Нет соединения»; при восстановлении подключения каталог обновляется автоматически. Для первого запуска с загрузкой товаров нужен интернет.

Корзина доступна без сети и восстанавливается между запусками. Добавление, изменение количества и удаление сохраняются локально, сумма пересчитывается автоматически.

Оформление заказа доступно только при наличии соединения. Без связи переход из корзины и отправка формы заблокированы; введённые данные сохраняются на экране до восстановления сети.

## Обработка ошибок

- В репозиториях `guardNetwork` преобразует ошибки Dio и разбора JSON в типизированные `AppException`: нет сети, таймаут, ошибка клиента (4xx), сервера (5xx) или некорректный ответ. Для известных HTTP-кодов есть отдельные типы; ошибки локального хранилища представлены `StorageException`.
- `EmptyResponseInterceptor` обнаруживает отсутствие обязательного тела ответа до разбора Retrofit. Пустой массив `[]` считается корректным результатом; допустимый по контракту `null` сохраняется.
- Cubit/Bloc перехватывают ожидаемые исключения и переводят экран в состояние ошибки. При неудачном обновлении каталог сохраняет предыдущие данные, а ошибка записи корзины сохраняет её последнее успешное состояние.
- `userErrorMessage` выбирает понятное сообщение из общей локализации. Диагностический текст сервера не выводится в интерфейсе. При ошибке первой загрузки доступна кнопка «Повторить», а ошибки соединения и сетевые таймауты в каталоге запускают автоматические повторы.

## Проверки

```sh
fvm flutter analyze
fvm flutter test
```

Unit-тесты покрывают операции и сумму корзины, восстановление кеша, успешную загрузку, сетевые ошибки и пустой результат. Widget-тесты проверяют состояния каталога Loading / Error / Success, корзину и валидацию/оформление заказа.

## Ограничения и дальнейшие шаги

- Расширить документацию проекта.
- Разделить навигацию по фичам: вынести объявления маршрутов в отдельные route-файлы внутри соответствующих фич.
- Подготовить документацию для QA: описать автоматизированные и ручные тест-кейсы с предусловиями, шагами и ожидаемыми результатами.
- Перевести проект на английский: добавить английскую локализацию интерфейса и перевести документацию.
- Реализовать тёмную тему приложения.
- Создать и подключить иконку приложения и сплеш-экран.
- Настроить CI/CD: автоматический запуск анализа и тестов, сборку и доставку приложения.
- Настроить flavors для разделения сборок по окружениям (dev, staging, prod) с отдельными конфигурациями и идентификаторами приложения.
- Подключить AppMetrica и Firebase Analytics для отслеживания просмотров товаров, действий с корзиной и оформления заказа.
- Реализовать автоматизированные тесты производительности с выводом статистики: времени загрузки экранов, длительности кадров UI/raster и количества кадров, превысивших бюджет. Запускать на реальных устройствах в profile-режиме.
- Фотографии не сохраняются на диск: после перезапуска без сети показываются заглушки. Для полного офлайна с фото нужно добавить их локальное хранение.
- Оформление локальное, как предусмотрено ТЗ: после валидации формы генерируется номер заказа и очищается корзина. Отправки на сервер и истории заказов нет.
- Не добавлены интеграционные тесты на устройстве. Следующий шаг — проверить потерю/восстановление сети и перезапуск приложения с реальным хранилищем. Отладка производилась на эмуляторе IOS.
